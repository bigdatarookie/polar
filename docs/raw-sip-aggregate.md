# Remaining-only raw-SIP scope and source availability

The selected remaining3490 scope extends the existing import controller. It is
not a second loader. The first-unit and OpenFIGI namespaces and evidence remain
separate. The new `alpaca-raw-sip-remaining/1` adapter uses
`polar.raw-sip-aggregate-config/1` with mode, aggregate_ref, jobs_ref and seed_refs.
Refs are exact-byte absolute path/sha256 pairs. Provider mode admits only the
frozen aggregate plan c687eb3b and remaining-jobs 62ad45b2. The original full
catalog 9ede957d and completed first-unit aded6413 are pinned by that plan. No
private roster, body or credential is packaged in Git.

The 3490-job/6980-GET/512-MiB-response/10800-original-second/one-executor/minimum
one-second/two-page/no-retry/no-redirect envelope is an **internal finite scope**,
not a provider API quota. Its namespace is imports-rawsip-aggregate-v1/planSHA
(fixture scope is separate), and plan IDs start rawsipaggregate- or
rawsipaggregatefixture-. Existing import-plan/status/execute/resume/attempt/
terminal/consume/control CLI methods dispatch the same store and controller.
Authority schema remains polar.raw-sip-execution-authority/1; its unit_sha256
now binds the selected aggregate plan for this profile. An operation still
needs its actual independent source qualification and finite operational /
expected-observed runtime / credential-reference / wake-consumer binding.
Schema validity is not invocation authority. This implementation grants no
provider call, new account, financial run, service change or database operation.

The canonical raw request job identity remains the first qualified raw-SIP
request identity: changing scope cannot rename an identical request or poison
metadata caches. The source-plan job ID and population-record ID remain distinct
fields. Every GET start, response body, cursor, commit and checkpoint keeps the
same durability order. An unknown in-flight start is charged a whole response
envelope and is never silently reissued. Complete empty and partial-date-history
successes are reusable; no rows is not a zero price, delisting or a new pending
job. The selected roster already excludes every completed first20 request and
four earlier compatible scopes. Seeds, when supplied, must match exact requests
and validated complete body/cursor chains. Unknown or partial jobs cannot be
imported as complete. HTTP429 stops this aggregate with a durable provider pause;
it does not retry the failed request or burn the remaining catalog blindly.
The pause is evidence for the operation owner, not a new authorization/reset.

All attempts in this scope share one original deadline and cumulative starts /
bytes. Batching/resume cannot replenish them. The old first20 counters and
lineage are retained as ancestry, not relabelled as new operation starts.
Within the same10800 seconds,300 seconds are held back from new GET dispatch
for source-envelope materialization. Materialization checks the original
monotonic deadline per row/publication; failure retains the captured evidence
and a named source gap. It never grants a fresh provider deadline to repair it.
Similarly,256MiB inside the same20GiB scope is reserved for the terminal
checkpoint/manifest and control evidence, rather than filling the whole scope
with unfinished data members and losing the stopping outcome.
The executor validates persisted immutable graphs on entry and uses only a
task-local immutable-record cache while holding its existing kernel lock.
The mutable control channel is never cached; it remains readable across
processes. No persistent shadow result index decides source cache acceptance.

Normalized output streams into <=16-MiB bars members, each within an unchanged
polar.partial-raw-pv-source-content/1 packet. Jobs can span packets; global
job/status and per-packet segment indexes make that explicit. Empty/failed/
unrequested jobs remain represented. Raw body/array/row/page pointers and exact
numeric tokens survive, including out-of-window rows. A collection manifest
pins every packet/member and the complete ordered job index. Existing HYP003
Sources checks each packet; no larger single file or raised generic32-MiB
ImportStore limit is needed. A packaging/storage gap retains raw evidence and
an incomplete/partial terminal outcome rather than refetching.

`polar hyp003-availability CONFIG --output-dir NEW_PRIVATE_DIRECTORY` reuses
Sources, the accepted quality checker, and exact raw pointer parsing. The
complete wire definition is src/polar/hyp003_availability_schema.json. Config
is polar.hyp003-availability-config/1: mode INVENTED or RETAINED,
population_ref, grid_ref and inputs. Retained mode binds exact R0 71f3f93b and
date grid b12d8480. Every one of3514 source records gets all1008 ordered date
positions (3542112 slots), even when no source input covers it. Equal aliases
do not collapse different source-record IDs.

Inputs are exact source envelopes or collections plus optional links_ref for
legacy record/profile declarations. New packet producer jobs carry explicit
record/request links. Legacy inputs without those links do not authorize an
alias/economic join: unlinked row positions are preserved separately, and an
unverified profile remains DECLARED_NOT_VERIFIED. Complete empty, complete
request gaps, partial/unknown, conflict and unrequested states remain distinct.
Each cell retains per-profile/revision states and all observed field-position
refs; conflicting exact source tokens never get an automatic winner. Unknown
clocks are never populated from capture time. Source rows outside the reference
grid remain in the observation index. This is not feature, label, signal,
coverage fitness, universe or financial acceptance.

Availability projection processes one bounded packet and one source record at
a time, using task-owned scratch files rather than a new database or service.
Each output member is <=16MiB and input/output scratch have explicit20GiB
component bounds. Source acquisition plus consumer peak must ALSO fit the
selected aggregate20GiB additional/actual64GiB-total allowance, measured and
reserved together by the operation owner; these component limits confer no
entitlement to consume40GiB. Existing artifacts are never cleaned to make room.
The output directory must be new, private and outside Git. Its content manifest
is written last and is the only completion marker. Failure leaves an incomplete
owned directory, not a usable revision or a reset/retry. The report command
`polar hyp003-availability-report DIRECTORY` verifies the content identity and
every output member hash. Actual dataset qualification and research consumption
remain with DE/Quant A after independent code qualification.
