# HYP003 partial-input preparation v1

`polar hyp003-prepare CONFIG --output-dir PRIVATE_ROOT` and `polar hyp003-preparation-report ID --output-dir PRIVATE_ROOT` dispatch before Settings/Service/DB. `polar.hyp003_preparation.prepare_partial_input(config)`, `write_preparation(result, root)` and `read_preparation(root, id)` expose the same offline layer. There is no HTTP, provider operation, retry/capture/cache mechanism, job, strategy, formation, feature, return/NAV or financial algorithm. Acceptedbase Gym/fixture APIs and limits stay unchanged. HOLDPR24 is not inherited or required by the pure raw preparation path.

Config schema `polar.hyp003-preparation-config/1`: adapter_version1, purpose DEVELOPMENT|EXPLORATORY|CONFIRMATORY_PREPARATION, hypothesis_ref, definition_ref, inputs list. Each input has adapter equal to `polar.current-class-roster-content/1` or `polar.partial-raw-pv-source-content/1`, absolute directory, manifest_sha256, optional relative manifest (default content-manifest.json), optional receipt `{path,sha256}`. Optional evidence_inputs admit only explicitly pinned metadata ancestor/sample manifests; sample schema `polar.current-class-sample-content/1` is evidence only. Parent/source objects can be admitted by ancestry_objects `{directory,path,sha256,role:SOURCE_PARENT_RECORDS|REFERENCE}`. No unadmitted capture_root, symlink or URI is followed. Optional proposed_reconstruction_ref, qualified_universe_ref, proposed_interval, proposed_grid and coverage_policy_ref are declarations, not admission.

All declared member hashes/lengths and JSON structure are verified; NDJSON is streamed with per-line hashes/structure boundaries. Local limits: config64KiB, manifest1MiB, JSON32MiB, NDJSON128MiB, line256KiB, total512MiB,32manifests,64JSONdepth,1millionrows/member. Output tables256MiB each/1GiBtotal and report1MiB are finite adapter bounds, not global project resource quotas or changes to history_bundle defaults. Source fractional JSON number tokens are represented as their exact lexical strings, never binary64; original immutable bytes remain hash-pinned. Actual raw O/H/L/C/V fields are already strings and remain unchanged. Decimal construction/comparison validates finite lexical domains without arithmetic or ambient rounding. Source defects in a valid envelope stay named row quality; corrupt/unsupported envelopes fail closed without publishing a preparation.

Fixed private tables: raw_rows.ndjson, parent_relations.ndjson, source_parent_records.ndjson, metadata_jobs.ndjson, transport_evidence.ndjson and source_metadata.ndjson. Supplied rows, parent relations, manifests, unknown fields, producer job records, complete response alternatives, failed/unassigned bodies and receipt/reuse provenance are retained. There is no ticker/FIGI economic merge or parent/candidate dedup. Metadata transport identity is versioned request context plus exact individual request; exact response aliases coalesce only as one logical job version with every provenance reference. Conflicting successful versions remain CONFLICTING_SUCCESS with no selection. Per-position assignment requires one explicit admitted capture witness, original request hash, full response hash/length, matching request/ordinal and inline response equality. Ambiguous or unadmitted pointers are incompatible input, not invented assignments.

Metadata UNRECEIVED means no assigned result, not proof of no request; failed batch evidence remains separate. Observed candidate count is source alternatives only, never eligible N. Raw requested/observed/missing and parent state counts are structural source breadth; no coverage policy or scientific reconstruction is applied. Separate current metadata snapshots and the raw producer's older projection remain identified, with supplied reference verification depth. Missing actions/calendar/class/economic identity remain UNRESOLVED; source frameT, declaredR and qualifiedU stay separate, eligible_N=null, formation/signal/financialNOT_RUN. Zero raw volume is valid; missing/invalid fields remain null/text with reasons. Adjusted/unknown volume cannot become qualified rawV. EstimatedK/its label stays separate from original nullable observed clocks, actual capture/import receipts and source-asof mapping.

`polar.hyp003-preparation-report/1` binds the six table hashes/bytes/counts, inputcontent revisions, adapter code and declared purpose/definitions. ID is hyp003prep-SHA256(codec.canonical(report_without_preparation_id)); no invocation/outputroot/environment or separately supplied physical receipt content enters it. Immutable producer content may itself contain source capture provenance; that fixed source object is retained, not rewritten into historical knowledge. A new separately supplied receipt does not rename identical semantic input. Physical invocation receipts separately bind config/source receipt hashes, actual UTC time and runtime. Outputroot is explicitly private/outside Git; existing publication/fsync/descriptor primitives reject conflicting bytes, never overwrite a report. Repeat identical content has the same semantic ID and a distinct physical invocation receipt. Read verifies identity and all table hashes, emits only the report, not private table bodies.

No source/parse/component result is financial, confirmatory coverage, live provider or actual QuantA consumer acceptance. DE retains original5f chain through independent technical QA and actual owner consumption. Synthetic cases and full actual compatibility depth are separate evidence. No generic universe/Lead/scientific approval gate is added.
