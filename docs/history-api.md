# Bounded private history reads

The new read-only routes consume registered immutable history revisions. Existing fixture routes, `/readyz`, retained reports/links and UI remain unchanged. No provider capture, normalization, schema migration, registration, indicator calculation, experiment or worker job is triggered by a read. Private sole-owner noncommercial source restrictions remain; loopback hosting is not permission for other-human/public/business access.

- `GET /v1/history/readyz`: history dependency readiness and bounded first chart-ready publication probe. A ready empty catalog has `chart_data_available=false`. This is separate from legacy readiness, indicators, UI integration and independent qualification.
- `GET /v1/history/datasets?limit=50&cursor=...`: small chart-ready summaries, stable catalog registration-sequence snapshot. No bars/raw payloads/local paths. Entirely unusable revisions stay available through explicit detail, outside the default catalog.
- `GET /v1/history/datasets/{dataset}/revisions/{revision}`: immutable revision, primary receipt, manifest, instruments/bases/count/date/quality summaries.
- Append `/assets?limit=50&cursor=...` for paged mapped assets; zero-valid assets retain their own null bounds and NOT_READY fitness.
- Append `/bars?instrument_id={id}&start=2024-01-01&end=2025-01-01&limit=1000&warmup_sessions=200&cursor=...` for ascending observed bars; start inclusive/end exclusive, one asset and at most 20*366 days per request.

Use returned pinned IDs and cursor without substituting mutable “latest”. Assets/bars cursors bind projection, revision, primary receipt/manifest, bases, selected asset/window, limit/warmup and last row. Catalog cursors bind their snapshot and limit. Different endpoint/selection/parameters or malformed/oversize cursors are rejected. Query names cannot be unknown or repeated; numeric parameters require plain decimal digits, without signs/fractions/leading zeros. Dates and ASCII IDs are validated strictly.

Every page is at most 1 MiB of encoded JSON; bars are at most 1000 TOTAL rows including warmup. Byte-limited pages return fewer rows and a correct next cursor. Consume all pages before committing a coherent requested chart. `window_complete` means the final requested page was returned, not complete exchange-calendar coverage. Do not use transport warmup to choose a recursive indicator seed; numeric series are outside this component.

Optional warmup is up to 2500 preceding admitted observations, paged first as `row_role=WARMUP`; visible rows are `VISIBLE`. Warmup reports requested, available and returned-on-this-page counts. With no request it is NOT_REQUESTED; fewer retained observations gives INSUFFICIENT_HISTORY; otherwise an unqualified calendar remains UNRESOLVED, not session/indicator readiness. An empty visible window returns EMPTY_WINDOW even if prior warmup is requested. Known quarantined asset records produce PARTIAL for a nonempty window; supplied valid rows otherwise are OBSERVED. These statuses do not certify calendar completeness. No padded sessions, carried prices or invented volume are returned.

Source OHLC/adjusted-close/volume remain exact decimal strings with separate raw/unadjusted, provider split/dividend-adjusted close and split-adjusted-volume bases. Zero volume remains an observed string zero. Historical event/publication/availability stays null when unsupported. Per-page identity, window, coverage and fitness remain explicit; expected/missing session counts stay null under the unqualified calendar. No strategy/NAV/Sharpe/reference/financial output is fabricated.

Malformed/out-of-bounds/unsupported queries and mismatched cursors return 422; unknown admitted revision/asset 404; corrupt retained identity/artifacts 409; unavailable history DB/schema/filesystem or inability to fit one bounded record 503 with a stable code. Errors never fall back to fixture data or echo DSNs, internal paths, raw bodies or exception messages. Existing registration integrity verification remains intact: a request verifies its bounded admitted first-profile archive (at most 20000 raw rows), then scans at most 5000 normalized rows for the selected asset. There is no full-market scan/cache/indexing service, and no full history embedded in each response.

Component tests use invented data/metadata doubles; author offline checks may inspect the retained private archive without PG mutation. Actual deployed DB/artifact/API/restart/UI qualification remains separate, using exact versions under the assigned runtime operator and independent System review.
