# Closed B11 private streaming operation

This source adapter hosts the accepted four-control/twelve-case signed pair producer using the existing `GymStore`/`HistoryStore`, scheduled-reference attempt namespace, private witness/chunk codecs and `process_budget` supervisor. It does not add a backtester, broker, queue controller, trial allocator, public result or serving endpoint. Legacy all-account producer and reader APIs remain unchanged by default. The new route is explicit and private.

## Local callable and metadata contract

`polar.signed_pair_operation.PairOperationService(root,storage_bytes)` provides `preflight(config)` and `run(config)`. The ordinary `Service.research_preflight` and `Service.research_run` facades/CLI dispatch schema `polar.private-pair-operation-config/1` to it. Use `polar research-preflight CONFIG_FILE` or `polar research-run CONFIG_FILE`. `stage` is ORIGINAL or SAVED. A bare research-recompute semantic ID is deliberately insufficient: saved verification also requires a separately selected bound SAVED config/authority through research-run.

The closed config contains namespace, stage, candidate_id, experiment_id, selection_ref, custody_ref, source_manifest_ref, method_ref, qualification_ref, resources_ref, authority_ref, code, code_revision, runtime_image_id, artifact_root_identity, expected_registry and semantic_id. Root identity is the existing path/device/inode descriptor; current code is the existing complete application code binding. Refs are exact immutable path/sha256/bytes metadata. ORIGINAL has no semantic_id; SAVED has no source_manifest_ref and consumes the original immutable semantic index only. There is no dynamic supplied Python loader, callback, shell command or plugin in this wire.

RETAINED is specifically the frozen B11 candidate/selection/card/source manifest/protocol and five controlling appendices. Preflight checks their exact pins and full expected input binding without opening `encoded_input`, calling PairInput preflight again, parsing quote/action tokens, computing features or entering native. It requires the existing prospective method and current technical qualification, explicit actor/root/runtime and resource admission, exact actual registry/prior and operative authority. No grant is generated. Metadata-only source qualifications already performed by DE are not repeated for receipts. Original tokens, sourcewrapper54b9 failure, additive source materialization and observed-null clock limitations remain immutable history.

After START only, the existing accepted encode/asdict/restore typed recipe reconstructs PairInput/Quote/Formation/Action from the pinned encoded input; its entire `binding_for` must equal the pinned accepted binding. Nominal original unadjustedValue, separate raw USD and adjusted SIGNAL, capture-local identities and conditional historical-access limitations are not changed by hosting. No new financial criterion, price precision, fee, activation or margin convention is selected here.

## Admission and debit

The family is a stable candidate/experiment/protocol/namespace identity, not an input/outcome-dependent retry key. Under the existing root lock the adapter compares all matching existing scheduled-reference starts across families with supplied expected_registry, rejects any previous original, and atomically no-clobber publishes START+config+one conservative original debit before any encoded values or producer entry. Candidate/card/selection, code/root/current authority and actual registry are rechecked inside the lock. Concurrent duplicates cannot both start. No reset, fabricated prior[], alias family or automatic retry is provided.

SAVED requires the exact original SUCCESS finish/graph/index, same current code/runtime, exactly its matching original registry entry, and no existing saved-verification start. It gets a separate immutable saved debit under the original attempt. Its selected wall/CPU cannot exceed the original prospective saved allowance; remaining cumulative resource allowance cannot exceed original remaining minus the measured containing original use. A failed/unfinalized original does not become eligible through an orphan graph or semantic index. Source-only delivery does not select either actual invocation.

Authority schema `polar.private-pair-operation-authority/1` binds stage, exact config binding hash (excluding authority_ref), resources hash, stable family, expected_registry and actual UID/GID. Strict integer scientific_calls/native_accounts/saved_calls/fit_calls/model_calls are respectively 1/48/0/0/0 for ORIGINAL, 0/0/1/0/0 for SAVED. Method/card/current technical evidence are independent pins, not author-created claims. Invented tests use explicitly invented artifacts, never real reservations or operative financial grants.

## Explicit resource contract and finite supervision

`resources_ref` schema is `polar.private-pair-resource-admission/1`. It requires status SUFFICIENT_CERTIFIED, actual root/UID/GID/runtime, a justified global_storage_headroom_bytes, and a closed limits object. An UNKNOWN/not-certifiable storage return cannot pass by substituting free disk or a per-store quota. RETAINED additionally compares actual Linux cgroup memory.max and cpu.max to the selected resource metadata and requires the bound external hosting guard ID/status. That external receipt is an SRE custody statement; the application does not claim independent Docker/host guard verification from an environment variable.

Limits have explicit positive integers for original/saved/collector `{wall_seconds,cpu_seconds}`, cleanup_seconds, remaining_family_wall_seconds, remaining_family_cpu_seconds, rss_bytes, log_bytes, journal_bytes, counter_bytes, partial_bytes, checkpoint_interval_events, operation_store_bytes, object_bytes and chunk_bytes. No B11 numeric allowance is supplied by source. Original prospective cumulative admission covers original+saved+two collectors+four cleanup envelopes; a saved invocation covers only its remaining saved+collector+two cleanups. Objects remain <=32MiB and existing compressed/unpacked chunks remain8MiB. Root quota and explicit object/counter/partial limits fail closed. Global64GiB is a storage ceiling, never a RAM claim.

Each work and collection child is run by the existing Linux process-group supervisor with explicit stage CPU/wall, RSS, bounded pipe-drained stdout/stderr, whole-record bounded resource journal and finite cleanup. Mandatory callsites persist before native/feature/decision entry. The child owns only its new process group; no host Docker/cgroup/controller mutation or broad signal is used. Group RSS is sampled and can miss short peaks; actual selected container hard memory constraints remain SRE hosting duty. Physical time limits include bounded polling/cleanup overshoot and exact receipts, not an assertion that a queue wait spends compute.

Before each stage, containing wall/CPU remaining is recomputed; the next child receives the smaller stage/cumulative remainder. At return, containing parent wall/CPU (self plus reaped children) is reported separately from disjoint supervisor stage receipts. Do not add containing totals to their own child stages. Parent setup/metadata/transport versus native versus saved/collector remains explicit; actual SRE outer physical guard and charge ledger remain required. No generic supervisor600/900 default, old1200/600/300, host free RAM or naive48 extrapolation becomes authority.

## Streaming, counters and partial recovery

The new pair iterator persists a completed immutable account packet/NAV/report before beginning the next account and releases its large object. It keeps only a small verified candidate receipt/reference and activation for controls. Such a receipt is regenerated from the actual verified candidate object; saved graph metadata cannot self-declare it. Control component manifests bind that exact candidate reference, and each source-absent reader verifies the candidate first, evicts it, then loads one control. Legacy direct verification still requires the actual candidate object when no internal streaming receipt is supplied.

Whole study membership/order is exactly four declared controls per each of twelve fixed cases. Full scalar reports are immutable per-account refs; only exact criterion operands are retained for the unchanged study clauses. This avoids retaining all48 exposure/margin tapes in the graph/evaluator. Full reports, data/fee/activation/candidate/source joins are independently recomputed one account at a time. Complete graph publication follows all48 completed/persisted members and quota checks; no partial graph is labeled SUCCESS. Economic default or policy failure remains distinct from a technical unfinalized process, without changing survival/criteria precedence.

Actual source load, scientific entry, account entry, native call entry, actual native account observation/completion, account completion/persistence and feature/decision entry are instrumented. An entry charge immediately before a call is not completion. Native/feature/decision/account boundaries always synchronously persist immutable counter records. Routine completed event/fill observations are buffered only until the explicit periodic checkpoint/boundary, with exact nonnegative increments reconciled by the collector. This removes excessive per-row fsyncs without deferring an entry debit. Periodic actual callback/END snapshots preserve current records, bridge prefix, NAV and D operands through the existing bounded chunk codec. Native partial exceptions force a checkpoint when possible.

The collector records last durable prefix counters as minima on failure, never invented zero totals after an unobserved frontier. OOM/timeout between checkpoints cannot be repaired by rerunning an account; prefix and current unknown frontier remain. Serialization/write/quota errors are retained independently. Completed member roots and checkpoints remain useful after later native or collection failure. A bounded collector child verifies durable sequence/increments, process return and complete membership; only a proper successful work+collector+cleanup result may finalize SUCCESS. Independent exact container cleanup remains SRE-owned.

Source/run/financial/publication acceptance remains independent.
