# Band existing publication reconciliation

research-input-reconcile is a closed read-only observation of the one preserved
Band config11 publication whose original native producer ended with
BAND_SOURCE_GENERATION. It never prepares or repairs source data. Original
publication/config/proof/file bytes and the original FAILURE remain unchanged;
the historical rejected response is UNKNOWN. Retained compatibility pins that
original config, manifest, code, runtime, claim80053 and failure terminal80057.
Other families and unreconciled inputs retain their ordinary rejection.

The request schema is polar.band-existing-publication-reconciliation/1. Fields
are schema, namespace, question_id, actor_session, consumer_task, code,
code_revision, runtime_image_id, artifact_root_identity, input_ref and
original_failure_ref. Current code/revision and actual Linux/runtime/root plus
the current scoped Data or Quant native claim are checked before saved input
verification and again afterward. Original failure reference is the original
task ID followed by #80057. Namespace RETAINED is mandatory for the actual
publication; INVENTED is only for named public test tasks.

The operation checks the original failed native claim/terminal/resolution,
original method/source purpose/spec and every saved file, saved normalization
pointers/relations/calendar/quality and exact original immutable identity. It
reads saved publication and qualification metadata; it never opens original
price members, reconstructs sources, fetches, computes policy or runs accounts.
Safe comparison operands are stored privately without queue bodies or source
values. An immutable task-specific request marker prevents automatic retries;
failure/uncertain effects must be reconciled before another action.

Use the existing CLI/Service or native_selected_tool operation
research-input-reconcile. Normal return includes observation_ref, input_ref
and producer_terminal_result. The status is
CURRENT_EXISTING_ARTIFACT_CUSTODY_AND_INTEGRITY_RECONCILED_WITH_LIMITS.
The observation and typed native terminal use distinct reconciliation schemas;
neither is polar.band-source-result/1. Atomic observation publication uses
HistoryStore under band-source-reconciliation-attempts, outside reference-inputs.
The operation does not close native tasks itself. The actual observer closes
its separate native producer task with the exact returned terminal result,
then runs research-input-preflight using the returned explicit input_ref.

The returned input_ref keeps the original manifest path/hash and adds an
external reconciliation_ref containing observation_ref and observer_task.
The reader verifies that separate terminal result and original failed lineage,
current actor/generation/code/runtime/root, full saved integrity and exact
observation binding before reading for a consumer. A task alone or uploaded JSON
success is insufficient. The current consumer must have the observer's accepted
code binding/runtime; its Git revision may differ without rewriting the old
producer identity. Band seed builders optionally accept reconciled_input_path
pointing to the returned input_ref JSON, alongside the original input_path.
The original input hash and ID remain unchanged.

Only new receipt files are written. No source publishing, rights/PIT/entity/
adjustment/K-vintage/investor upgrade, financial readiness or original
preparation success follows. Quant owns any later independently bound financial
operation. On any error preserve the original object and all new receipts;
never rerun config11 prepare or overwrite a failed producer.

Observation failures retain two private diagnostic files: custody-comparisons.json
contains expected/current actor, generation, claim and terminal metadata;
comparison-operands.json contains exact expected/actual file hashes, byte lengths,
descriptor identities, presence, original native transition/closure operands and
hashed saved relationship/status operands. No task/transition bodies, resolution
bodies, source rows or numerical values are retained in these diagnostics. Bound
or unreadable files record their observed metadata and an unavailable digest
rather than being read beyond the existing limit.
