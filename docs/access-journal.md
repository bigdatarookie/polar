# Bounded access notes helper

The standard-library `scripts/access_journal.py` helps participating agents read and append the existing Markdown access journal. It does not access providers, credentials, browsers or mailboxes. It creates no database, side index or service. Existing manual entries/routes remain byte-identical.

Use an explicit journal path and a bounded operation:

```sh
python3 scripts/access_journal.py --journal /absolute/path/NOTES.md read --provider example --recent 5 --max-bytes 16384
python3 scripts/access_journal.py --journal /absolute/path/NOTES.md append --event-file /private/path/safe-event.json
```

`--event-file -` accepts bounded JSON from stdin. Do not put credentials or event bodies in arguments. The helper does not discover credential references or rewrite/sanitize arbitrary text. Real access operations need their own authorization and provider-route check. Tests use disposable notes exclusively.

Events have exactly these fields: schema (`polar.access-event/2`), event_id (`ACCESS-` plus uppercase letters/digits/hyphens), utc (actual UTC second timestamp ending Z), actor, qitem, provider, operation, purpose, alias, outcome, observable_basis, attribution, new, unusual, blocking, blocker_class, method_environment, session_continuity, pacing_profile, missing_tools, user_action, safe_evidence, next_checkpoint, correction_ref and safe_author_assertion=true. New records also require episode_kind, access_problem and route_change.

All narrative fields use short lowercase alphanumeric/hyphen/underscore codes, not free prose. safe_evidence holds1..8 relative code-path references, not URLs, raw payloads or absolute private paths. Meaningful evidence can be linked using safe aliases; the helper does not open those references. outcome is success/partial/blocked/failed/unknown_effect; attribution is observed/reported/independently_verified. blocker_class is none/control/form/session/access/entitlement/rights/human/unknown, consistent with boolean blocking. new/unusual/blocking are actual booleans. correction_ref is null or a prior event ID; append corrections or route-revision events instead of rewriting history. There is no assertion that an arbitrary existing note or code-like string is secret-free: the author must choose nonsecret aliases/codes and supply the safe-author assertion. Names, emails, passwords, keys, cookies, verification codes, token URLs, headers and mailbox contents remain forbidden. Known sensitive markers and malformed fields are rejected with stable codes; this is not a universal secret detector.

Append takes a bounded advisory flock on the existing file, verifies its bounded snapshot and framed records, then writes one complete record using O_APPEND and fsync. The lock is on the file itself; there is no lockfile to delete. Same ID and canonical payload returns ALREADY_PRESENT; same ID with another payload or a manual heading collision returns EVENT_ID_CONFLICT. A lost write/fsync receipt returns UNKNOWN_WRITE_EFFECT. Retry by the same stable ID/payload inspects existing bytes first; do not invent another ID. Partial/checksum-invalid/unsupported framed records refuse further append/read with PARTIAL_OR_INVALID_JOURNAL rather than truncate or repair someone else's journal. A crash can leave a partial frame; a separate evidence-backed repair is required. Existing complete framed entries are validated, not accepted as proof of their attributed external episode.

Only cooperating writers respect flock; manual writers, path renames or unrelated editors may violate this protocol. The helper never replaces/truncates the target, follows symlink components, permits hard-linked/nonregular targets or deletes peer state. Unsafe/missing targets produce stable errors. An existing regular file is required. Dead processes release their OS locks. The lock wait is at most5seconds (default1); journals are bounded to2MiB and event inputs to8KiB. These are per-operation limits, not project storage budgets.

Read selects all matching ROUTE headings and the latest0..20 events (default5). Structured events match the exact provider field; manual notes/routes use a case-insensitive provider-word match, which is explicitly a heuristic. JSON reports matching/returned counts, journal bytes, selection policy and `incomplete` whenever event selection or the text byte budget omits content. Sections are never silently cut mid-section; a route larger than the budget can produce no text and incomplete=true. `max-bytes` bounds returned text (256..32768bytes); JSON envelope/escaping adds bounded overhead. A2MiB journal-limit refusal is explicit, not a claim that no provider route exists. The helper never runs a whole-journal retrospective automatically.

Author/component and controlled fixture checks do not establish external account access, source rights, historical data fitness, independent QA or financial readiness. QA Code owns independent review; System QA should verify disposable CLI effects before technical merge. Actual shared journal adoption is an operational step after review.


## v0.16 eligibility and historical compatibility

New writes use polar.access-event/2 and the existing safe fields plus exactly three classifications. episode_kind is registration (including email verification), login (including reauth/repeat login), session-recovery, credential-change, new-rights, access-problem or ordinary-operation. access_problem is none/auth/permission/session and records an actually observed symptom, not an inference from a credential helper mention. route_change is none/verified-new-method/verified-clarification; the author owns that verification and evidence. A declaration of access-problem with no observed problem is invalid.

Ordinary working-auth GitHub read/fetch/push/PR/review/merge and same-working-key API repeats produce SKIPPED_NON_EPISODE/exit0 and ZERO bytes appended. Use operation codes read/push/pr/review/merge/git-read/git-fetch/git-push/pr-read/pr-create/pr-review/pr-merge/api-call/api-repeat/repeat-api/same-key-api-call for these known ordinary operations. An explicit non-none observed access_problem upgrades even an ordinary operation to one problem episode; no failure is inferred from environment names. A genuine new-right check should use its explicit kind and a descriptive operation such as check-new-rights or api-probe, rather than mislabel it as a same-key repeat.

Summarize one access problem and all remediation attempts in one stable event after resolution, uncertainty or handoff. Do not append each retry, field fill or API call. Keep the collection in the existing task/proof until that episode boundary, not a new service/tracker. Unknown append completion retries the exact same canonical payload/ID and is idempotent. Same-ID changed payload remains a conflict; it is not an update mechanism. A successful repeat login is one compact record with new=false/unusual=false/blocking=false/missing_tools=none/route_change=none. Routine access success does not expand routes. A route-update/route-revision operation requires verified-new-method or verified-clarification; this helper still never rewrites or expands a ROUTE section automatically.

Legacy polar.access-event/1 frames retain their original structural validation and bytes. Historical parsing/read/collision checks do NOT run new-write eligibility. Existing exact legacy retries remain ALREADY_PRESENT (no new entry); collisions including both manual-heading orderings still fail before policy checks. A new unclassified v1 access record requires EPISODE_CLASSIFICATION_REQUIRED, while an identifiable new ordinary v1 operation can be skipped explicitly. No old PASS/FAIL/NOT RUN, source commit or ordinary operation entry is renamed/deleted/compacted.

Default read is a working overview of routes and access episodes: identifiable ordinary history is excluded with filtered_ordinary_events reported. Structured v2 uses explicit problem/category metadata; structured v1 recognizes known successful ordinary operations unless explicit access-recovery/new-right cues exist. Manual GitHub history uses a conservative documented provider/operation heuristic: explicit registration/login/recovery/access symptoms win, merely using a working helper does not. Ambiguous legacy entries stay visible and are counted as unclassified_legacy_events; this is not an independent retrospective access verdict. `read --provider github --include-ordinary` deliberately includes the original ordinary entries under the same input/output bounds for provenance. Neither read mode changes historical bytes or causes any retrospective automatically.

Current policy supersedes v0.15's every-routine-success assumption only for new eligibility/default overview. Original PR18/19 evidence remains historical. Author and independent checks use disposable notes; no real journal, credential/provider/mailbox/browser or account operation is required to test this amendment.
