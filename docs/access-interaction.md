# Helpers for the existing headed access path

`scripts/access-interaction.mjs` is a standard-library companion to the installed named `playwright-cli` path. It does not replace the adapter, launch a provider browser, import DE's private prototype bridges, create accounts or supply entitlement. A caller opens/reuses its authorized task-owned named headed CLI session and passes that exact session plus a mode0700 private task directory. The same directory/session must be used on resume; do not point it at a personal profile or an unrelated agent's browser.

`AccessSession` provides separately bounded seeded action/keystroke/scroll jitter, actual visible/unique/enabled/form-valid readiness, explicit nonsecret option selection, private field input, mutation checkpoints, verification navigation and safe aggregate receipts. Default jitter is600..1200ms between actions,40..100ms between characters,100..250ms between scroll steps; each configured range must be integer0..5000ms/min<=max. A seed is an integer0..2^32-1. Overall deadline is100..600000ms; each existing CLI invocation is bounded to remaining time/max60seconds. Readiness remains authoritative; random waits do not establish success or bypass service restrictions.

For example, import AccessSession into a task-owned private Node script, configure explicit permitted HTTPS host names, and call ready({role:'button',name:'the actual visible localized action'}) rather than clicking a hidden matching input. choose({selector:'the observed country select'},'TH') selects an explicitly justified option; it never infers country from city/timezone. scroll(pixels) has a separate pacing range. No adapter/package install or browser supervisor is introduced.

`mutate(stableId,operation,target)` checkpoints BEFORE dispatch (submit/login/verification/key-creation/api-probe), clicks once and records UNKNOWN_EFFECT. A click return does not prove account creation, login, verification, key creation or API success. A transport timeout/error also remains UNKNOWN_EFFECT. A restarted task sees PENDING/UNKNOWN_EFFECT and refuses another mutation with OBSERVE_BEFORE_RETRY. Inspect existing state through the same session first, then call observe(id,'confirmed'|'not-applied'|'unresolved', safeBooleanFlags). Confirmed/non-applied observations require a positive flag. A confirmed mutation returns ALREADY_CONFIRMED on repeat. HumanAction returns one allowed missing action (visible verification, country selection, entitlement or driver control) and the same session/checkpoint; no generic reapproval prompt.

The private directory contains an append-only access-checkpoints.jsonl with version/session/nonsecret operation ID/state/actualUTC only, bounded to64KiB per task. This is an operation-resume artifact, not a second task tracker or service. One task owner must serialize its access; there is no cross-process session arbitration. Partial/mismatched checkpoint files refuse continuation rather than guessing. Do not reuse it for a different account/purpose or delete it to bypass unknown effects. Browser state remains owned by the existing CLI session.

Private input references are explicit admitted JSON filename+field names under the already authorized private root. Supported DE shapes: alpaca-account.json(email,password), alpaca-api-credentials.json(endpoint,key_id,secret_key,scope), alphavantage-api-credentials.json(provider,api_key,purpose). PERSONA.txt and episode-specific bridges are deliberately not imported or executed; they have hardcoded mutating behavior and no reusable API. No directory scan, credential discovery, overwrite, capture or account creation is performed. Root must resolve to itself and be mode0700; selected file must be an owner-only regular file, single link, no terminal symlink, <=16KiB. The task owner must protect root/ancestors against concurrent rename: Node's path-open checks do not supply an openat traversal guarantee against a hostile ancestor writer.

`fillPrivate(root, reference, targets)` reads only selected fields internally, serves one private in-memory loopback response at a random path, and has the existing browser controller fetch/type it without literal values in argv or generated source. API-request transport is separate from provider activity. Script files are mode0600 in the private task directory and removed after the command; bridge closes in finally, with no request logging or CORS. Captured raw CLI output/stderr is bounded and never forwarded or persisted by the helper. No trace/screenshot/body dump is requested. Do not enable external tracing/snapshots around secret input. Private values remain in process/browser memory and cannot be reliably zeroed by JavaScript garbage collection; receipt fields contain aggregate profile intervals only. No assertion that arbitrary selectors, caller scripts, external CLI extensions or manually authored output are secret-free is made.

Verification selection requires one visible message row with exact provider/operation and an explicit visible localized label, then validates its destination. It does not read a mailbox or pick a generic email by date. allowedURL requires an exact allowlisted HTTPS hostname, no userinfo/lookalike/trailing-dot/other port; HTTP is available only for explicit127.0.0.1 fixtures. followVerification validates the initial URL and uses the existing Chromium Playwright CDPSession Fetch request-stage interception to inspect main-frame hops before an unapproved redirect can be followed. This narrow navigation guard requires the current Chrome/Chromium session; unsupported CDP fails closed before navigation, with no alternate adapter installed. It does not guard unrelated subresources, popups or other pages. Playwright routing alone sees only the original redirect-chain URL, as documented at https://playwright.dev/docs/network; CDP paused redirects are specified at https://chromedevtools.github.io/devtools-protocol/tot/Fetch/. Token-bearing URLs stay in memory/private action files, never receipts. There is no preflight GET that could consume a verification link twice. After navigation, observation is still required; a permitted URL alone does not prove verification.

qualification() keeps account/email/dashboard/APIauth/entitlement/required-data/rights/fitness as independent explicitly supplied states. A dashboard or HTTP200 never promotes another field. It does not implement an external API/data probe or scientific qualification. A caller must use its authorized bounded source operation and attach its separately verified outcome.

Cancellation limits remain those of the existing CLI/browser: terminating an owned CLI client does not prove an already-dispatched browser/provider effect was canceled. Helpers mark uncertain mutations UNKNOWN_EFFECT and require observation; no final successful episode receipt may claim settlement based on client termination. Known private typing loops check a browser deadline and each Playwright action has a timeout; arbitrary external callbacks are outside this guarantee. No unrelated process/browser/profile is closed. The controlled CLI fixture explicitly closes only its new named test session and local servers.

Checks: `node --test tests/access-interaction.test.mjs` uses synthetic component fixtures. `node tests/access-interaction.cli.mjs NEW_PRIVATE_DIRECTORY` explicitly opens one task-owned headed Chrome CLI session against a loopback synthetic form; it checks localized/conditional readiness, private sentinel input, delayed observation, same-session no-repeat and blocked unapproved redirect, then closes its session. It never opens a provider, reads real credentials or qualifies external access. Independent Code/System review remains required before operational adoption.
