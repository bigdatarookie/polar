# Retained source history for saved Orders navigation

This extends the existing history bundle verifier, immutable HistoryStore and
HistoryRegistry. It introduces no capture, alternate registry, engine or task
tracker. The selected retained SIP source bytes are reused for chart context;
research inputs, outcomes, Orders, signed reviews and scientific accounting do
not change.

`polar.retained-sip-history-bundle/1` preserves the exact DE source-candidate and
content-correspondence evidence, selected OHLCV rows and original captured bodies.
`history_retained.assemble(candidate_bytes, evidence_bytes, rows_by_sha,
bodies_by_sha, input_sha, metadata=metadata_by_sha)` is a pure deterministic
constructor. It has no filesystem, network, store, policy, native or evaluation
calls. The existing register command admits the resulting bundle only with its
expected manifest hash; current operation custody must first bind the actual DE
qualification/source pins. Constructor success is not a data/financial verdict.

Verification reassembles every content byte. Each selected row's source body
hash, exact `/bars/SYMBOL/index` pointer, selected-date/index binding, original
aggregation label and exact numeric token strings must agree. OHLC ranges,
typed counts, sorted unique dates, bounded files and null historical clocks are
checked. Adjusted sources bind the original collection, parent request and body
pin. Raw sources bind the original HTTP receipt/body and literal SIP/raw request
URL. This preserves the selected source snapshots and declared current symbols;
it does not establish permanent security identity, PIT availability or unseen
history. The DE evidence remains attributed source qualification under queue
custody, not a cryptographic provider signature.

Raw AMZN SIP and vendor-all-adjusted SHY/VTI SIP remain separate bundles/bases.
No MODEL100 rescale, raw-versus-adjusted relabel, substituted demo revision,
synthetic candle or separate adjusted-close series is invented. `adjusted_close`
is null; fractional vendor volume tokens retain their supplied units. The old
EODHD four-asset/28-member contract remains intact. New bundles use at most64
bounded members through the same publication graph and additive registration.
Import-receipt metadata says retained projection, with no new capture clocks.

Registered summaries carry exact research-input hash/native-alias/instrument
correspondence. The Orders path consults that existing registry only for the two
selected user lineages and re-verifies the immutable publication. Multiple
matching revisions fail closed; no newest/ticker-only choice is made. Legacy
input070 mapping is unchanged. Unregistered, missing or ambiguous correspondence
cannot enable a row. Successful registration supplies dataset/revision IDs from
actual content, not a manually guessed mapping. Only saved FILLED events produce
date-lane markers; zero-delta/unrouted entries never become fills. Marker position
is date-only and raw OHLC price-overlay compatibility stays false, including for
coarse100 MODEL prices.

The browser accepts only the explicit closed basis descriptions and labels the
source candles/volume truthfully. Existing raw-EODHD indicator calculations are
not reused for unsupported retained bases: settings are retained but those
series are explicitly unavailable. Source OHLC and saved result NAV/order prices
remain separate. Final user acceptance requires actual AMZN TOM and SHY row
clicks selecting the correct source instrument/date/exact fill and stable date
marker after qualified serving and additive registration; HTTP200 alone is not
acceptance.

The selected pointer census preserves two explicit original metadata forms.
Adjusted/SIP claims use typed `source_row_index`. The original multiyear raw
source-map form uses typed `source_row_ordinal_0based`, plus its exact
`source_array=bars.SYMBOL`, symbol, bars.ndjson member and nonnegative chunk/request
ordinals. Both bind the staged row's original body hash/date/index and original
raw array token. Ambiguous dual indices, booleans, wrong symbols/arrays and
malformed normalized line metadata reject. The constructor accommodates the
original producer metadata; it does not rewrite the candidate or source rows.
